# RESONATE OS CAMPAIGNS. THE OPERATOR DECLARES THEM HERE.
#
# EMPTY ON PURPOSE. Awaiting the operator's marks against the campaign table
# (`docs/CAMPAIGN-TABLE-2026-10-02.md`). Nothing may be added by code, by an
# agent, or by inference from a campaign's name.
#
# WHAT THIS FILE DECIDES, AND WHAT IT DOES NOT
#
# It decides ATTRIBUTION: whether a send found at the provider counts as ours.
# That matters for two things only - the `legacy_touched` flag with its send
# count, and keeping the response rate of genuinely fresh leads separate from
# leads we have written to before.
#
# It does NOT decide whether a lead may be contacted. Under the operator's
# rule of 2026-10-02 the ONLY blocking signal is a REPLY. Membership in an old
# campaign, in a paused campaign, or in a HeyReach list blocks nothing. Do not
# reintroduce a block here.
#
# WHY A DECLARED LIST AND NOT JUST THE LEDGER
#
# `providerwrites.classify_campaign` already answers `resonate_os` from
# `work/campaigns.jsonl`, and for campaigns this code created that is enough -
# they need no entry here. The gap is historical: `work/campaigns.jsonl`
# begins 2026-09-02, so it cannot claim a campaign created before that, and
# the provider cannot be asked. EmailBison's campaign record carries no owner,
# creator, user, team or tenant field - confirmed across all 29 listing keys
# on 2026-09-28. A title carrying a person's first name is free text with no
# referential integrity: a hint, never a measurement.
#
# So this file exists for the campaigns the ledger cannot claim and the
# provider cannot name.
#
# ABSENCE IS NOT OWNERSHIP, IN EITHER DIRECTION
#
# A campaign that is neither recorded in the ledger nor declared here is
# UNKNOWN. Under invariant 0 an UNKNOWN attribution never becomes "ours" and
# never becomes "theirs". A send on an UNKNOWN campaign is counted as a send
# we cannot attribute, and it is reported as such rather than silently
# dropped into either bucket.
#
# FORMAT
#
#   <provider> <campaign id>        # optional comment
#
# `provider` is `bison` or `heyreach`. `campaign id` is the PROVIDER's own
# number, not a canonical row id - the canonical rows are already in the
# ledger. One per line. Blank lines and `#` comments are ignored.
#
# Example, not active (it is inside this comment block):
#
#   bison 274        # declared OS by the operator on <date>
#   heyreach 599020  # declared OS by the operator on <date>
#
