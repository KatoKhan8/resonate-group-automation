## Executive Summary

The codebase is large (~190 modules in `src/`, ~12 provider modules) and many components are well-built in isolation. The recurring defect is **disconnection**: modules that compute correctly but whose output no downstream workflow reads. Three confirmed examples: `learning.py` (imported only by its own test), `contextpack.py` (consumed only by the web UI, not by generation), and the email→LinkedIn stop (wired, tested, sealed, and incapable because it read `linkedin_url` where the store carries `linkedin`).

The five-step email cadence and multi-step HeyReach cadence are intact and well-guarded. The copy engine v2 (stages A–H) is implemented with the correct cost shape (cheap models for research, Sonnet for prospect-facing text). The safety infrastructure (reviewapproval, providerwrites, spendledger, copylint, sequencegate) is real and load-bearing.

What does NOT exist: a Client Second Brain as a structured store (productive.yaml covers much of the content but is not indexed or retrievable by section), an Offer Engine, a Skills/SOP system, semantic repetition detection, person-relevance scoring for signals, a learning loop that feeds back into strategy, and contextual retargeting.

## Section 7: Copywriting Approach

### What exists

The v2 copy engine is implemented across three modules:

| Module | Lines | Purpose |
|--------|-------|---------|
| `copyprompts.py` | 550 | Stages A (ICP qualification) and B (research extraction). Cheap model (Groq). |
| `copystages.py` | 351 | Stages C (hypothesis), D (value match), E (sequence strategy), F (copy generation with Sonnet). |
| `generate.py` | 2,153 | The generation pipeline. Orchestrates stages, manages the plan, handles failures. |

The cost shape is correct: stages A–E run on Groq (cheap), stage F runs on Sonnet (prospect-facing text only). The cohort system prompt (`COHORT_SYSTEM` in `copyprompts.py`) is cached per batch.

### What works

- The eight-stage pipeline (A through H) is implemented and tested.
- Standing paragraphs from productive.yaml are no longer sent whole; Sonnet writes from a per-lead hypothesis.
- The sequence strategy (stage E) is decided BEFORE copy generation (stage F), so step objectives are set by construction.
- `sequencegate.py` (231 lines) checks the whole sequence for repetition, as-fact phrasing, question duplication, and capability monotony.
- `copylint.py` (443 lines) checks per-message rules: dashes, buzzwords, traceability of specifics to pack facts, step count.

### What is missing

- **Example library:** No curated collection of successful/unsuccessful examples with metadata. The spec asks for examples with target persona, industry, campaign objective, offer, message type, actual copy, why selected, performance evidence.
- **Semantic repetition detection:** `sequencegate.py` uses lexical overlap (word intersection / shorter message length). No embeddings, no cosine similarity, no semantic check. The spec asks for semantic validation where it materially improves detection.
- **Offer consistency check:** Cannot exist without an offer engine.
- **Signal-to-person relevance in copy:** No check that a signal mentioned in copy is relevant to the specific recipient.

### Confirmed rules preserved

- No dashes: `copylint.DASH_RE` + `lint.SUBSTITUTED_PUNCTUATION`. Enforced.
- No invented URLs: `copylint` traceability check requires specifics to appear in pack facts.
- No unsupported claims: `sequencegate.AS_FACT_RES` catches hypothesis-stated-as-finding patterns.
- Correct threading: `productive.yaml` `email_sequence` defines threading per step. `bisonfactory.py` renders it.
- Correct sender identity: `senderidentity.py` + `clients.sender_identity`. 
- Correct LinkedIn personalization: `heyreachfactory.py` maps cadence steps to graph roles.

## Section 8: Copy Validation

### What exists

| Module | Lines | Checks |
|--------|-------|--------|
| `copylint.py` | 443 | Per-message: dashes, buzzwords, step count (5), traceability of specifics to pack facts, first-line uniqueness across batch |
| `sequencegate.py` | 231 | Sequence-level: lexical overlap between steps, questions asked twice, capability monotony, as-fact phrasing, hedging |
| `lint.py` | ~300 | Draft-level: greeting, length, placeholders, attachments, banned phrases, dash substitution |
| `bisonfactory.py` | 2,036 | Factory-level: copy lint, tenancy check, approved copy check, empty-render refusal |
| `heyreachfactory.py` | 1,567 | Factory-level: approved LinkedIn copy required for every role, refusal if missing |

### What works

- Lexical overlap detection across email steps (`sequencegate.overlap()`).
- Question deduplication across email and LinkedIn (`sequencegate._questions()`).
- Capability monotony check (`sequencegate` `batch_capabilities`).
- Empty-render gate in `bisonfactory.py` (refuses when a step would render blank).
- Traceability: `copylint` extracts specifics (figures, dates, quoted phrases, proper nouns) and requires each in the lead's pack facts.

### What is missing

- **Semantic repetition:** Only lexical overlap is checked. Two messages sharing no words but making the same argument pass.
- **Cross-channel repetition (semantic):** LinkedIn vs email argument repetition is not checked semantically.
- **Offer consistency:** No offer engine means no check.
- **Signal-to-person relevance:** Not checked.
- **Correct message objective per step:** Stage E sets objectives but no gate verifies the generated copy matches the objective.
- **LLM quality score override:** Not implemented. The spec says "Do not allow an LLM quality score to override deterministic safety failures." No LLM quality score exists, so this is vacuously preserved.

## The HeyReach Cadence — What It Actually Does

### Cadence definition

`PRODUCTIVE_LI_HEAVY_V1` in `src/cadencelibrary.py` (lines 327–370):

| Step | Day | Channel | Action | Graph Role |
|------|-----|---------|--------|------------|
| li1 | 1 | LinkedIn | Connect | connection_note |
| em1 | 1 | Email | Generated | — |
| li2 | 3 | LinkedIn | Message (requires CONNECTED) | connected_1 + message_2 |
| em2 | 4 | Email | Generated | — |
| li3 | 6 | LinkedIn | Message (requires CONNECTED) | connected_2 + message_3 |
| em3 | 8 | Email | Generated | — |
| li4 | 10 | LinkedIn | Message (requires CONNECTED) | connected_3 + message_4 |
| em4 | 12 | Email | Generated | — |
| li5 | 15 | LinkedIn | Message (requires CONNECTED) | connected_4 |
| em5 | 21 | Email | Generated | — |

**Five LinkedIn steps, five email steps.** li3 has an InMail alternative that is OMITTED by default because `INMAIL_ELIGIBILITY_DETECTABLE` is False.

### Graph structure

`heyreachfactory.py` `_build_sequence_no_inmail()` builds a graph with three branches:

1. **Already connected:** li2 → li3 → li4 → li5 (four messages, no invite needed)
2. **Not connected, accepts:** li1 (invite) → li2 → li3 → li4 (four messages)
3. **Not connected, does not accept:** li1 (invite) → VIEW_PROFILE → END (no InMail)
4. **Open profile:** bypasses connection, goes straight to messages

### Which steps render

Every step that has approved copy renders. `heyreachfactory._refuse_missing()` refuses the entire staging if any required role lacks approved copy. A step with no copy does NOT silently drop — the factory raises `FactoryRefused`.

**The previous measurement finding (ONE LinkedIn step surfacing from a six-step graph) is NOT the current behavior.** The current factory refuses if copy is missing. The graph has five LinkedIn steps and all five are populated when copy is approved.

### What was fixed since that measurement

The duplicate-message bug on the already-connected branch (li2 mapped to both connected_1 and message_2, which sat back-to-back on that branch) was fixed on 2026-09-14. The branches now have DIFFERENT LENGTHS and use different steps:

- Not connected yet: li1 → li2 → li3 → li4
- Already connected: li2 → li3 → li4 → li5
