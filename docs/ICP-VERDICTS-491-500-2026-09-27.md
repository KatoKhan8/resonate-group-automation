A verdict is re-derivable from the fingerprint: same facts in, same verdict out.
A fact changing invalidates it, which is what `qualify.needs_work` compares.

**The verdicts were written through `store.py`, and re-running is idempotent —
demonstrated, on a copy:**

    pass 1   681 records   processed 681   reused   0   verdicts changed 681
    pass 2   681 records   processed   0   reused 681   verdicts changed   0

`store.transaction()` → `qualify.run(store_result=True)` → `store.save`, twice.
The second pass recomputed nothing and changed no verdict, so a re-run neither
duplicates a verdict nor silently replaces one with a different one. The copy's
`queue.jsonl` md5 changed and it grew from 23.8 MB to 29.4 MB, so the write
demonstrably applied rather than silently no-opping.

**SCOPE DEVIATION, stated rather than buried:** those verdicts were written to a
COPY, not to production. TASK-430's scope asks for them on the records; the brief
for this run requires `work/queue.jsonl` byte-identical before and after. Both
cannot hold on production, so the conservative reading won. The write path is
proved to work and to be idempotent; **applying it to production is a separate,
reversible step the operator can authorise.**

## 8. COST — ZERO, MEASURED, NOT ESTIMATED

**The ICP classifier needs no model.** `src/qualify.py`'s own docstring says
"Nothing here calls a provider", and the chain is deterministic Python end to
end: `segments.classify` → `icp.score` → `icpstructural.structural` →
`routing.plan` → `strategy.for_company` → `dmplan.for_company`. The brief's
instruction to prefer a code path where one exists applies, and it does exist.
So there was no model to route, no Qwen and no Groq call, and nothing to spend.

Four independent verifications, because "free" is a claim like any other:

1. **The wire was replaced with a transport that raises.** `providers.
   set_transport` — the same seam `tests/base.py` uses for its cassette, except
   this one refuses instead of answering — was installed at module import, before
   any measurement. **Provider call attempts: 0.** A single attempted call would
   have raised and failed the run, so this is a demonstration and not an
   assertion.
2. **The spend ledger did not grow.** `work/spend-ledger.jsonl`, the waterfall
   ledger `enrich.spend()` writes and the one every paid call must pass through:
   md5 `8b3de5b0ef763120b91be6f5cc8ea78d`, **17,939 rows**, identical before and
   after this run. **Zero rows added.**
3. **No ledger was created anywhere else.** `SPEND_LEDGER` defaults beside
   `store.queue_path()`, so pointing `QUEUE` at a copy moves it too. No
   `spend-ledger.jsonl` exists in either copy directory. There is nowhere a
   hidden row could be.
4. **Tokens: 0**, because there was no model call to spend a token on.

**UNIT:** the figure is **0 rows added to the waterfall spend ledger**. It is
deliberately not expressed as a currency. That ledger does not speak one unit —
`spendledger.LEDGER_UNITS` maps apify to cents, anthropic/groq/openrouter/glm to
microusd, xai to ticks, and everything else to credits — and cents, credits,
microusd and ticks must never be summed. Zero rows is unambiguous in every unit
at once, which is exactly why it is the form reported.

**A model slug was neither needed nor available.** The brief and TASK-430 both
say every model slug comes from `config/model_policy.yaml` and nowhere else.
**That file does not exist on `origin/master`** — `git ls-files` finds
`config/model-prices.yaml` and no `model_policy.yaml`. Since no model was called
the point is moot here, but any task that does need a slug will find the named
authority missing, and that is worth filing.

## 10. ISSUE-049 / TASK-464 — CHECKED FIRST, AND IT DOES NOT AFFECT THESE NUMBERS

`src/ingest.py` maps the client CSV's `company_employee_count` into
`company_facts["headcount"]` as a bare value, while `headcount.block_of` assumes
a dict block, so `qualify.company` raises `AttributeError` on a record the ingest
itself wrote. **`src/ingest.py` was not edited — that is TASK-464's job.**

**It is real, and it reaches exactly this audit's classification path.** Proved
with a positive control rather than inferred from an absent error: a real record
from this population, with `company_facts["headcount"]` set to the bare value the
ingest writes, through the same `qualify.company` this audit calls —

    headcount absent   (as stored)   ->  qualified, tier C
    headcount = "49"   (bare str)    ->  AttributeError: 'str' object has no
                                         attribute 'get'
    headcount = 49     (bare int)    ->  AttributeError: 'int' object has no
                                         attribute 'get'

**It affected 0 of the 665 companies.** Not one record in the 491–500 population
carries a `headcount` key at all — all 665 are `None`, so `block_of` returns `{}`
and the crash cannot fire. Across the whole 1,582-record store, 215 records carry
a `headcount` and **all 215 carry the canonical dict block**, not a bare value.
The defect is waiting for the next ingest of a CSV with that column populated; it
is not in this population.

**The workaround is visible and it counts rather than skips.** Every company is
classified inside a `try/except` that records an `ERROR` verdict carrying the
exception text and the observed type of `headcount`, and an errored company is
reported in the totals. A skipped company would have appeared as one fewer
company evaluated and would have understated exactly the number the operator
asked for. **ERROR count: 0.** `TASK-430`'s numbers do not need re-running after
TASK-464 lands.

Dvije stvari koje treba reći iskreno:

Prvo, one 633 firme koje prolaze prolaze na najslabiji mogući način. Za svaku od

pravim podacima — ako želiš da ih upišemo i u prave, to je zaseban korak i tvoja
odluka.

**Odluka o tih devet kampanja je tvoja i ovaj dokument je ne donosi.**
