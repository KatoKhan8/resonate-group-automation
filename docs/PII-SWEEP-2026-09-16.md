## 5. Name Slugs (Hyphenated Patterns)

**15,150+ occurrences in 400+ files.**

These are hyphenated patterns like `ray-kingman`, `uk-digital`, `hand-written`.
Most are false positives (compound words, test identifiers, CSS classes).

**The problem:** A name like "Ray Kingman" becomes `ray-kingman` when used
as a `contact_key` or slug. The guard does not catch this because it checks
for exact name matches, not name-shaped patterns.

**True positives (name-shaped slugs):**
- `scripts/task174_investigate_481.py`: `contact_key` field contains
  name-shaped slugs in plain text (the TASK-174 leak).

**False positives (vast majority):**
- Test identifiers: `uk-digital`, `hand-written`, `cross-tenant`
- CSS classes: `sign-in`, `event-stream`
- Compound words: `re-read`, `well-formed`, `load-bearing`

**Action required:** Strengthen the guard to detect name-shaped slugs in
specific contexts (e.g., `contact_key` fields, variable assignments).

## Why the Guard Missed a Name in a Slug

The guard checks for exact substring matches against `FORBIDDEN_NAMES`. A
name like "Ray Kingman" would be caught if "kingman" or "ray kingman" was
in the list. But:

1. **The name is not in the list.** `FORBIDDEN_NAMES` has 38 entries. It
   does not include "kingman", "faertz", "karas", etc.

2. **The slug is a different shape.** `ray-kingman` is not the same string
   as "Ray Kingman". Even if "ray kingman" was in the list, the slug would
   not match.

3. **The field name is not PII-shaped.** `contact_key` does not look like
   a PII field. The guard does not check field names.

**The gap:** The guard tests for known values, not shapes. A name-shaped
slug in a field called `contact_key` falls through because:
- The value is not in `FORBIDDEN_NAMES`
- The field name is not recognized as PII
- The shape (hyphenated lowercase) is common in code
