## THE FOUR THINGS THIS ESTABLISHES

**1. The pipeline delivers.** Ingest -> enrichment -> ICP -> contact ->
verification -> generation -> lint -> claims -> approval -> stage -> schedule
-> SEND, end to end, to a real address, with no bounce. Every one of those
stages had been exercised offline and none of them had ever been proven
against a real recipient.

**2. A `scheduled_date` CAN be honoured to the second.** It fired 20 seconds
after the scheduled time. The earlier checkpoint recorded this same campaign's
scheduled time MOVING once overnight, 13:19Z -> 16:24Z, with nothing staged
in between, and concluded "a `scheduled_date` on this provider is an
intention, not a commitment". Both observations stand: it moved once and then
fired on time. One send does not make a contract.

**3. Zero bounce on a verified address.** The verification waterfall produced
an address that accepted mail. One address is not a deliverability rate, but
it is the first evidence any of it works.

**4. The local event log agrees.** `hotsoupgroup-com` carries a `push_marked`
event, which is in `touch.CONFIRMING_EVENTS`, so the system's own count of
confirmed touches is 1 rather than 0 for the first time.

## WHAT IT DOES NOT ESTABLISH, AND ONE TRAP

**`opened: 0` MEANS NOTHING HERE.** Campaign 451 has `open_tracking: False`.
The provider is not measuring opens on this campaign, so that zero is the
absence of a measurement rather than the absence of an open. Anybody reading
these numbers later will be tempted to treat it as "sent but not read". It is
not evidence of that or of anything else.

`replied: 0` is real but young - roughly ninety minutes after a single send to
one person. It is not a reply rate and cannot become one at n=1.

**This proves nothing about the copy.** The canary carried one hand-reviewed,
human-approved email. It says nothing about the generated five-step sequence,
whose defects are documented separately and are still being fixed.

**And it proves nothing about LinkedIn.** HeyReach 599020 has never sent
anything and still holds the defective sequence.

## WHAT TO WATCH NEXT

Replies arrive over days, not hours. The watcher writes a sample every three
minutes to `%TEMP%/451_watch.jsonl` and will record a reply if one lands while
it runs; it does not survive a machine restart.

    replied / unique_replies    the only outcome that matters here

A reply to this address must be handled through `inbound.handle`, which is the
path that classifies it and applies the account policy. Nothing automated
follows this send: 451 holds one lead, its sequence has one step, and it is
`completed`.
