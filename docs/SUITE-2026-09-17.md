## Classification of every red test

### Category A: Fixture problem — `bisonfactory._sequence_steps` thread_reply enforcement (28 tests)

**Root cause:** `bisonfactory._sequence_steps` now refuses steps where a
follow-up carries a distinct subject without `thread_reply: true`. The error:

    FactoryRefused: step 3 is not a thread reply but carries a distinct subject
    ('{SUBJECT_3}' vs opener '{SUBJECT_1}'). Only the opener owns a subject;
    follow-ups must be thread replies referencing the opener's subject.

**Affected modules and tests:**

- `test_bison_campaign_write` (11 ERROR): all tests calling `_sequence_steps` with `CONTROL_CADENCE_STEPS`
- `test_render_preview` (11 ERROR): all tests calling `render_preview("email_five")`
- `test_task081_thread_reply` (6 ERROR): all tests calling `_sequence_steps` with `PRODUCTIVE_LI_HEAVY_V1`

**Classification:** Fixture problem. The cadence fixtures (`CONTROL_CADENCE_STEPS` and `PRODUCTIVE_LI_HEAVY_V1`) have follow-up steps with distinct subjects but no `thread_reply: true` flag. The factory enforcement is correct; the fixtures need updating.

**Fix required in tests/:** Update `CONTROL_CADENCE_STEPS` in `test_bison_campaign_write.py` and the cadence steps in `test_task081_thread_reply.py` to set `thread_reply: true` on follow-up steps, OR update the `PRODUCTIVE_LI_HEAVY_V1` cadence in `src/cadencelibrary.py` (but `src/` is forbidden for this task).
