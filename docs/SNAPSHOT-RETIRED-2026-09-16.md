# The queue snapshot is retired, 2026-09-16

**Decision:** RETIRE. Option (b) from TASK-204.

**Effective:** Immediately. No new task should read `work/queue.snapshot.jsonl`.

---

## What the snapshot was

`work/queue.snapshot.jsonl` was a manual copy of `work/queue.jsonl`, taken by
an operator and stamped with a timestamp and commit SHA in
`work/queue.snapshot.STAMP`. It was intended as a stable read-only reference
for Qwen workers to analyse without touching live state.

The last snapshot was taken at `2026-09-15T17:52:12+00:00` from master `cf23154`,
holding 550 records. It is now stale: live state has been mutated by a free-path
run (TASK-171) that added company_facts to 250 records, moved 150 into ICP
review, and 100 into ICP rejected.

## Why it is retired

1. **Nothing writes it automatically.** No script, no cron, no hook regenerates
   the snapshot. It was always a manual copy that went stale the moment live
   state changed. A stale artefact that looks authoritative is worse than a
   missing one.

2. **It caused at least two measured wrong answers in one day.**
   - TASK-194 measured "143 contacts held by insufficient_confirmations" from
     the snapshot. TASK-196 showed the real figure was 159 contacts with no
     verification evidence at all, and exactly 1 that Deliverable would help.
     Claude repeated the 143 in a commit message and a document before it was
     checked.
   - The snapshot reports `icp_status: NONE` for all 550 records (the field was
     not populated at snapshot time), while live state has 65 verified with
     verdicts.

3. **The manifest already serves its purpose.** `docs/state/QUEUE-MANIFEST.json`
   (generated by `scripts/durable_state.py`) provides a sanitised, regenerable
   view of the queue: record counts, stage distribution, client counts, estate
   fingerprint. It is regenerated on every run of `durable_state.py`, carries
   no PII, and is in git.

4. **50 of 60 reader scripts are stamp-blind.** They read the data without the
   date, making it impossible for a caller to know they are reading stale data.
   Only 10 scripts also read the STAMP file.

5. **No code in `src/` reads or writes it.** The `Snapshot` class in
   `src/store.py` is an in-memory optimistic concurrency mechanism, completely
   unrelated to the file. The snapshot has zero integration with the production
   code path.

## What replaces it

| Need | Use instead |
|------|-------------|
| Read current queue state | `src.store.load()` → `work/queue.jsonl` (live, in Claude's worktree) |
| Sanitised view for durable state | `docs/state/QUEUE-MANIFEST.json` (in git, no PII) |
| Point-in-time measurement for a task | Read live state at measurement time, stamp the finding with the queue mtime |
| Cross-worktree access | The manifest is in git. Live state is only in Claude's worktree. |

## The mechanism that makes a stale read impossible

`scripts/task204_snapshot_loader.py` returns a `SnapshotData` object that
bundles records AND stamp inseparably. A caller cannot get the data without
the date. The loader also:

- Raises `FileNotFoundError` if either the snapshot or stamp file is missing
- Compares the snapshot stamp against the live queue's mtime when both exist
- Compares record counts between snapshot and live queue
- Sets `is_stale = True` with a `staleness_reason` when any discrepancy exists

Any future code that needs to read the snapshot (should not happen, but if it
does) must go through this loader. The raw `open("work/queue.snapshot.jsonl")`
pattern is now known to be dangerous.

## Proof that nothing unique was destroyed

1. **The snapshot is a copy of live state.** It was created by `cp work/queue.jsonl
   work/queue.snapshot.jsonl`. The original data lives in `work/queue.jsonl` in
   Claude's worktree (`C:\Users\Zvonimir\Desktop\resonate-group-automation\work\queue.jsonl`).

2. **Live state has MOVED PAST the snapshot.** The free-path run (TASK-171)
   mutated live state after the snapshot was taken. The snapshot is now a
   subset of the truth - it holds 550 records from before the run, while live
   state holds 550 records from after. No record in the snapshot is absent
   from live state (the run did not delete records, it advanced them through
   stages).

3. **The manifest captures the current shape.** `docs/state/QUEUE-MANIFEST.json`
   was regenerated by TASK-191 from live state and shows 550 records with
   current stage distribution.

4. **This worktree has no `work/queue.jsonl`.** The snapshot is the only queue
   data in this worktree. It is NOT being deleted from this worktree in this
   task (the task forbids writing to `work/`). The recommendation is that
   Claude deletes it from worktrees that have it, after confirming live state
   is the authority.

## The 60 scripts that read the snapshot

Full list produced by `scripts/task204_affected_scripts.py`:

- **60 scripts** in `scripts/` and `tests/` reference `queue.snapshot.jsonl`
- **10 are stamp-aware** (also read `queue.snapshot.STAMP`)
- **50 are stamp-blind** (read data without the date)
- **1 is known to have produced a wrong finding:** `task194_analysis.py`

All 60 are one-off analysis scripts that have already run. Their findings are
recorded in task result blocks and docs/ files. The scripts themselves are
historical artifacts. No repointing is needed because none will run again.

### The one known wrong finding

| Script | Task | Wrong number | Correct number | Source of correction |
|--------|------|-------------|----------------|---------------------|
| `task194_analysis.py` | TASK-194 | 143 contacts held by insufficient_confirmations | 159 contacts with no verification evidence; 1 would benefit from Deliverable | TASK-196 |

### Other scripts whose findings MAY be stale but were not independently re-measured

Every script that measured a count, percentage, or state distribution from the
snapshot produced a number that was true at snapshot time but may not be true
now. The TASK-191 document (`docs/FUNNEL-2026-09-16.md`) lists 26 documents
carrying "300 records" from the old snapshot and 5 carrying "316 queued" from
the pre-free-path state. These are historical records and are not edited.

## What changes in QWEN.md

The QWEN.md section that says:

    work/queue.snapshot.jsonl    a read-only copy of production
    work/queue.snapshot.STAMP    when it was taken, and from which commit

Is replaced with guidance to use live state or the manifest. The snapshot
files remain on disk in worktrees that have them (they are gitignored) but
are no longer referenced as an authority.

## What does NOT change

- `work/queue.jsonl` and `work/campaigns.jsonl` are untouched. They are the
  live state and are owned by `src/store.py`.
- `docs/state/QUEUE-MANIFEST.json` continues to be generated by
  `scripts/durable_state.py`.
- Historical documents that cite the snapshot are NOT edited. They are records
  of what was measured when. A reader needs the list in TASK-191's document to
  know which numbers are stale.
- The snapshot files themselves are NOT deleted by this task. Deletion is
  recommended to Claude, who can confirm that live state is the authority
  before removing them from each worktree.
