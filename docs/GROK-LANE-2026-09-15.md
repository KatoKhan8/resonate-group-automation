# Grok Lane — xAI Adapter

**Date:** 2026-09-15
**Task:** TASK-157
**Status:** Adapter built, not wired into production paths.

## Purpose

The Grok lane is LIVE INTELLIGENCE and mid-to-high reasoning. It sits between
Qwen and Claude in the capability routing chain:

    DETERMINISTIC PYTHON -> CACHE/EVIDENCE -> QWEN -> GROK -> CLAUDE

Grok's lane: recent developments, hiring, launches, partnerships, leadership
changes, funding, ambiguous ICP, evidence challenger, Qwen quality judge.

**Grok does not replace the crawler.** The evidence order stays: structured
data → cached company evidence → free crawler → Grok only where incremental
value is expected.

| Credential env var | `XAI_API_KEY` | — |

The request body is OpenAI-compatible:

```json
{
  "model": "grok-4.6",
  "messages": [{"role": "user", "content": "..."}],
  "max_completion_tokens": 4096,
  "temperature": 0.7,
  "tools": [{"type": "web_search"}]
}
```

### Cost Tracking

xAI returns `cost_in_usd_ticks` in the `usage` object of every response.

- **Unit:** 10,000,000,000 ticks = $1 USD
- **Scope:** Covers all model decodes and every tool invocation in the
  agentic loop. One field, no separate accumulation needed.
- **Conversion:** `xai.ticks_to_usd(ticks)` → float USD amount.

Source: [Cost Tracking](https://docs.x.ai/developers/cost-tracking).

### Usage Fields Captured

| Field | Source | Description |
|-------|--------|-------------|
| prompt_tokens | usage.prompt_tokens | Total input tokens |
| completion_tokens | usage.completion_tokens | Total output tokens |
| total_tokens | usage.total_tokens | Sum |
| cached_tokens | usage.prompt_tokens_details.cached_tokens | Reused cached tokens |
| reasoning_tokens | usage.completion_tokens_details.reasoning_tokens | Tokens spent on reasoning |
| cost_in_usd_ticks | usage.cost_in_usd_ticks | Actual billed amount |
| num_sources_used | usage.num_sources_used | Live search sources used |
| server_side_tool_usage | server_side_tool_usage | Tool invocation counts |

### Bounds

| Bound | Value | Rationale |
|-------|-------|-----------|
| max_completion_tokens | 8192 (cap) | Prevents unbounded output |
| max tool calls | 10 | Prevents runaway tool loops |
| max search tools | 3 | web_search + x_search + one more |
| temperature | 0..2 | API range |
| timeout | 60s | Per-attempt |
| max retries | 2 | 5xx only; 4xx fails immediately |

No agentic loop may run unbounded.

### Tools: OPT-IN

`web_search` and `x_search` are **opt-in per call**, never defaults. The
adapter's `chat()` function accepts a `tools` parameter; if the caller passes
none, the request body carries no `tools` key and the model cannot invoke any
server-side tool.

- **web_search:** Grok searches the web and browses pages.
  [Docs](https://docs.x.ai/developers/tools/web-search)
- **x_search:** Grok searches X posts, users, and threads. $5 per 1,000 calls.
  [Docs](https://docs.x.ai/developers/tools/x-search)

Running live research for every company automatically is the expensive mistake
this lane exists to avoid.

### Credential Rule

`XAI_API_KEY` is read from the environment only. Never printed, logged,
persisted to JSONL, put in a task file, a test, a doc, a commit, a worker
prompt, or an exception message. Read the NAME, never the value.

If absent:
- `check()` returns `{"ok": False}` with `"XAI_API_KEY"` in the note.
- `chat()` raises `MissingKey("no XAI_API_KEY in config/.env")`.
- Every caller degrades to its existing route.

An absent credential is a routing fact, not an error to swallow.

## What This Does NOT Do

- **Not wired into production.** `generate`, `qualify`, `research`, and `llm`
  are untouched. Claude integrates.
- **No provider writes.** Grok may never activate, resume, bypass approval,
  collision, tenancy, fatigue, caps, or history.
- **No evidence promotion.** A Grok answer is a claim with a source, or it is
  not evidence. Generated model text must never become its own evidence.

## What It Takes to Route One Real Stage Through It

1. **Pick a stage.** The best candidate is "evidence challenger" — a stage
   that questions cached evidence against live data. It is read-only, bounded,
   and has a clear success criterion (the cached evidence is confirmed or
   contradicted with sources).

2. **Add the call site.** In the module that owns the stage (e.g., a new
   function in `src/research.py` or a new module), import `xai` and call
   `xai.chat(messages, tools=[{"type": "web_search"}])`.

3. **Handle the response.** Extract `content` as the claim, `usage` for cost
   attribution, and any citations from the response. The caller must attach
   source URLs to the claim; a Grok answer without sources is not evidence.

4. **Gate on the credential.** Before calling, check `xai.check()["ok"]` or
   catch `MissingKey`. If the key is absent, degrade to the existing route
   (Qwen or cached evidence).

5. **Cap the spend.** Set `max_tokens` to the minimum the stage needs. Use
   `temperature=0` for deterministic output. Do not pass tools the stage does
   not need.

6. **Test against the cassette.** Add a cassette entry to
   `tests/fixtures/cassettes/xai.json` for the new call pattern. The test
   must assert on the trimmed return, not the raw payload.

7. **Verify the wiring.** `grep -rn "xai.chat" src/` must find the call site.
   If the only hit is the definition, the integration is not connected.
